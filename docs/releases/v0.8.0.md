# Release v0.8.0: Bundle Scope Isolation & Canonical Scope Naming

Release `v0.8.0` introduces declarative **Bundle Scope Isolation** via `scopes` in the root `knowledge/index.md` frontmatter and removes the legacy `bundle` alias for `--scope` across the CLI and MCP server. Because removing the `--scope bundle` alias is a breaking CLI/MCP schema change, this is a minor release (`v0.8.0`).

---

### 1. Breaking Changes & Migration

* **Removed the legacy `bundle` alias for `--scope` (`okf search` and MCP `okf_search`).**
  - `--scope` now accepts only the canonical scope names: `all`, `project`, `vendor`, `user`, and `system`.
  - Passing `--scope bundle` (or `"scope": "bundle"` in MCP `okf_search`) now returns an invalid-scope error.
  - **Migration:** Replace `--scope bundle` with `--scope project`. The `--bundle <dir>` flag and the MCP `"bundle"` directory parameter remain unchanged.

---

### 2. Features

* **Declarative Bundle Scope Isolation (`scopes` in root `knowledge/index.md`).**
  - Projects (such as client repositories, open-source projects, or isolated domains) can now restrict which memory layers are active by declaring an explicit `scopes` list in the root `knowledge/index.md` frontmatter (both flow lists and block lists are supported):
    ```yaml
    ---
    okf_version: "0.2"
    scopes: [project, vendor]
    ---
    ```
  - **Default Behavior:** When `scopes` is omitted, all four canonical scopes (`project`, `vendor`, `user`, `system`) remain active.
  - **Implicit Filtering:** Disabled scopes (e.g. `user` and `system` in the example above) are automatically skipped during `--scope all` searches (`SearchLayered`) and bare-ID `okf show` / `okf_show` fallback (`ResolveScopedConcept`).
  - **Strict Enforcement:** Explicit queries targeting a disabled scope (e.g. `okf search --scope user`, `okf show user:secret`, or `okf://user/secret`) are rejected with an error: `scope "user" is disabled by bundle configuration in index.md (allowed: project, vendor)`.
  - **Fail-Closed Validation:** Declaring an empty `scopes` key (`scopes: []` or `scopes:`) or any non-canonical value (such as `all`, `bundle`, or a typo) immediately fails bundle loading and `okf validate`.
